> 有看不懂的术语先翻最后一节「小词典」。

## 1. 一句话理解这个项目

一关的流程是三段式：

```
拼图（点确定判定）→ 探索（走路、捡东西、进门）→ 切下一关
```

这三段由 `LevelDirector` 串起来。**每个模块只做自己的事，模块之间不直接调用，只靠"广播"和"数据"说话。**

```
        LevelDirector（导演：决定现在演哪一幕）
              │  喊一嗓子
              ▼
        GameEvents（广播喇叭：谁关心谁自己听）
         │            │            │
    拼图模块      角色模块      对话模块
```

例：

```csharp
// 导演喊："进入探索阶段了"
GameEvents.RaiseExplorePhaseEntered(context);

// 你的角色脚本自己听：
void OnEnable()  { GameEvents.ExplorePhaseEntered += HandleExplore; }
void OnDisable() { GameEvents.ExplorePhaseEntered -= HandleExplore; }

void HandleExplore(LevelContext ctx) { SetControlEnabled(true); }
```

**重点**：喊的人不知道谁在听，听的人不知道谁在喊。所以你可以随时加新模块，不用改别人的代码。

## 3. 你的四个任务（按难度排，一个做完再来做下一个）

### 任务 1：角色移动 ⭐ （最简单，从这里开始）

**目标**：拼图阶段角色完全不能动；进入探索阶段后能用方向键/WASD 走。

**为什么重要**：拼图阶段的方向键是**留给拼图用的**（←→ 是在挪拼图块）。如果角色同时响应方向键，就会出现"一边拼图一边走路"。

**做法**：
1. 新建 `Assets/Scripts/Player/PlayerController.cs`
2. 实现 `Remiehzla.Flow.IPlayerControl`（两个成员：`SetControlEnabled(bool)`、`Transform Player`）
3. 订阅两个事件开关自己：
   - `GameEvents.PuzzlePhaseEntered` → 冻住
   - `GameEvents.ExplorePhaseEntered` → 放开
4. 移动用 `Input.GetAxisRaw("Horizontal"/"Vertical")`，`transform.position += dir * speed * Time.deltaTime`

**验收标准**：
- Play → 拼图阶段按方向键，拼图块能挪动、**角色纹丝不动**
- 拼对点确定 → 进入探索 → 角色能走

**照抄这里**：`Assets/Scripts/Explore/TempPlayerController.cs`（37 行，我已经写了一个临时版）
**做好了以后告诉我**，我把那个临时文件删掉。

### 任务 2：交互检测 + 提示 ⭐⭐

**目标**：走到可交互物旁边显示提示文字，按 E 交互。

**做法**：
1. 每 0.3 秒扫一次场景里的 `IInteractable`（**不要每帧扫**）
2. 挑距离最近、且 `CanInteract == true` 的那个
3. 显示它的 `Prompt`（例："捡起合照"）
4. 按 E 调 `Interact(gameObject)`

**关键点 —— 永远不要自己判断"能不能交互"**：

```csharp
// ❌ 错：自己判断条件
if (distance < 1.5f && !是已经捡过的) { ... }

// ✅ 对：只信 CanInteract
if (target != null && target.CanInteract) {
    target.Interact(player);   // 它自己知道条件满不满足
}
```

**验收标准**：走到合照旁边出现"捡起合照"，按 E 后合照消失、右上角"已收集"数字 +1；走到门旁边出现"进入下一关"。

**照抄这里**：`Assets/Scripts/Explore/TempInteractor.cs`（85 行）

> 交互提示的高亮描边（边缘发光）还没定，先只做文字提示。

### 任务 3：对话系统 ⭐⭐⭐（最难，最后做）

**目标**：把现有的 `Assets/Scripts/Dialogue/OpeningManager.cs` 改造成"能被流程调用"的服务。

**现在的三个问题**（改造就是修这三条）：

| 现状 | 要改成 |
|---|---|
| 台词写死在 Inspector 的 `string[]` 里 | 抽成 `DialogueAsset`（ScriptableObject，装 `DialogueLine[]`），一关一个资产 |
| `Start()` 里自动播放，别人调不动 | 提供 `Play(DialogueAsset, Action onComplete)`，播完回调 |
| 只有 `Debug.Log("对话播放结束")` | 用回调 / 事件通知调用方 |

**顺手修掉一个性能坑**：

```csharp
// ❌ 现在的写法：每个字拼一次字符串，TMP 每改一次 text 就全文重排版
dialogueText.text += letter;
yield return new WaitForSeconds(typingSpeed);

// ✅ 正确：文字一次性赋完，只推进"可见字符数"
dialogueText.text = fullSentence;
for (int visible = 1; visible <= fullSentence.Length; visible++) {
    dialogueText.maxVisibleCharacters = visible;
    yield return null;      // 用计时器控制速度，不要每字 new WaitForSeconds
}
```

**验收标准**：写个临时测试脚本，`Awake` 里调 `Play(某个对话资产, () => Debug.Log("播完了"))`，能看到打字机效果、播完打日志。

**顺带要做**：
- 按任意键/点屏幕推进一句（现在只能点按钮）
- 按住跳过（一长段演出会困住玩家）

### 任务 4：转场 ⭐⭐

**目标**：实现 `Remiehzla.Flow.ITransitionService`。

```csharp
void Play(Action atMidpoint, Action onComplete = null, float fadeOut = 0.4f, float fadeIn = 0.4f);
```

**做法**：一张全屏黑 `Image` + `CanvasGroup`：
1. alpha 0 → 1（用 `fadeOut` 秒）
2. **调 `atMidpoint()`** ← 这一刻画面全黑，我这边用它切阶段/换场景
3. alpha 1 → 0（用 `fadeIn` 秒）
4. 调 `onComplete()`

**验收标准**：调用 `Play(() => Debug.Log("黑屏时切"), () => Debug.Log("亮了"))`，两个日志的时机对得上。

**注意**：`IsPlaying` 要在转场期间返回 true，防止连点触发两次。

## 4. 常见错误清单（照着自查）

| ❌ 错误 | ✅ 正确做法 |
|---|---|
| `FindObjectOfType` 写在 `Update` 里 | 在 `Awake` 里找一次存起来 |
| `text = text + xxx` / `string.Format` 每帧 | 只在值变化时更新 |
| `GetComponent<T>()` 不判空直接用 | `if (x != null)` |
| 订阅了事件但没退订 | `OnEnable` 订阅 / `OnDisable` 退订 |
| 把文件放到 `Packages/` 里 | 一律放 `Assets/Scripts/你的模块/` |
| 手动删 `.meta` 文件 | 永远跟着 `.cs` 一起提交，不要单独删 |
| 直接改我的脚本 | 先问 |
| 改完不 Play 就提交 | 至少跑通一遍主流程 |

## 6. 小词典

| 术语 | 一句话解释 |
|---|---|
| `MonoBehaviour` | 挂在场景物体上的脚本，才有 `Update`/`Start` 这些"生命钩子" |
| `ScriptableObject` | 存在 Assets 里的**数据文件**（不是组件），策划改它不用改代码 |
| 组件（Component） | 挂在物体上的功能块，比如 `SpriteRenderer`、`BoxCollider2D` |
| 预制体（Prefab） | 存好的物体模板，拖到场景里能实例化很多个 |
| 事件（event） | "广播"，`X += 方法` 订阅，`Invoke` 触发 |
| 接口（interface） | 一份"你必须提供这些方法"的清单，实现它 = 签合同 |
| `pivot` | 图片的旋转/定位中心点，2D 角色一般放**底部中点** |
| `SortingGroup` | 让一个物体的多张 sprite 作为**整体**排序，别散着排 |
| `Canvas` | UI 的绘制容器，`sortingOrder` 越大越靠前 |
