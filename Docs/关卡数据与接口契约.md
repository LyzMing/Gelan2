## 2. 职责划分

| 模块 | 归属 | 说明 |
|---|---|---|
| 拼图网格、切图、交换/旋转/翻转/复制、判定 | **拼图组** | 现有 `PuzzleGrid` / `PuzzleTile` |

| 对话系统与对话 UI | 对方 | 通过 `IDialogueService` 暴露 |

| 存档读写 | **拼图组** | 对方若需要读写 flag，走 `ProgressService` |

## 3. 阶段状态机

每个关卡是一个独立场景，场景里同时有「拼图根节点」和「探索根节点」，同一时刻只激活一个。

```
 Boot / 关卡加载
        │
        ▼
 ┌──────────────┐   入场剧情播完
 │  LevelEnter  │─────────────┐
 └──────────────┘             ▼
                       ┌──────────────┐
                       │    Puzzle    │
                       └──────────────┘
                              │  点「确定」，且与某个 Solution 完全一致
                              ▼
                       ┌──────────────┐  玩家走到门并交互
                       │   Explore    │─────────────┐
                       └──────────────┘             ▼
                                              ┌──────────────┐
                                              │  LevelClear  │ → 转场 → 下一关
                                              └──────────────┘
```

要点：

1. **判定时机是「点确定」，不是拼好的瞬间。** 拼好了不自动跳转，允许玩家继续调整。
2. 判定失败：给一次视觉反馈（抖动 / 红闪）+ 提示，**留在拼图阶段**，可继续修改或重新打乱。
3. 进入 Explore 后，整个拼图根节点（含 Canvas、缩放平移逻辑）被禁用，所以「不能再缩放拖动视角」是**结构上保证**的，不需要额外写禁用逻辑。
4. 最终演出关：`LevelDefinition.puzzle == null`，跳过 Puzzle 阶段直接播剧情。

## 4. 数据契约

### 4.1 LevelDefinition（ScriptableObject，每关一个资产）

```csharp
[CreateAssetMenu(menuName = "Remiehzla/Level Definition", fileName = "L00_NewLevel")]
public class LevelDefinition : ScriptableObject
{
    [Header("标识")]
    public string levelId = "L01_HOME";     // 存档键 + 收集品 id 前缀，全项目唯一
    public string displayName = "家";

    [Header("拼图阶段")]
    public PuzzleConfig puzzle;             // null = 纯剧情关（最终演出关）

    [Header("探索阶段")]
    public string exploreSceneName;         // 本关场景名（拼图与探索同一个场景）

    [Header("剧情")]
    public DialogueAsset introDialogue;         // 拼图之前的演出，可空
    public DialogueAsset clearedDialogue;       // 判定通过、进探索之前（策划案的"定格0.3s+快门声"放这里）
    public DialogueAsset outroDialogue;         // 走到门之后，可空

    [Header("收集品")]
    public CollectibleDef[] collectibles;       // 本关可拾取物，id 建议 "L01_PHOTO" 形式
}
```

### 4.2 PuzzleConfig（内联，不单独出资产）

```csharp
[Serializable]
public class PuzzleConfig
{
    [Header("图片")]
    public Texture2D image;                 // 正方形整图
    [Range(2, 8)] public int gridSize = 3;  // 2×2 / 3×3 / 4×4 …（正方形，格数逐关递增）

    [Header("初始状态")]
    public PuzzleLayout initial;            // 策划摆好的打乱状态（不是运行时随机）

    [Header("正解（可多个）")]
    public PuzzleSolution[] solutions;

    [Header("允许的操作")]
    public PuzzleOps allowedOps;

    [Header("步数（暂不惩罚）")]
    public bool countRotateAsStep;          // 旋转/翻转是否计入步数
    public int moveLimit;                   // 0 = 不限

    [Header("调试")]
    public bool allowShuffleInGame;         // 游戏内是否允许按 R 重打乱（正式关卡建议关）
}
```

### 4.3 格子状态 / 布局 / 解

```csharp
[Serializable]
public struct CellState
{
    [Tooltip("原图第几块（0 = 左上角，行优先）。-1 = 错乱块（不显示图块，可被复制覆盖）")]
    public int pieceIndex;

    [Tooltip("顺时针转了几个 90°（0~3）")]
    public int turnSteps;

    public bool flipped;
}

[Serializable]
public class PuzzleLayout
{
    public CellState[] cells;   // 长度 = gridSize * gridSize，行优先（0 = 左上角）
}

[Serializable]
public class PuzzleSolution
{
    public string solutionId = "normal";  // 传给探索阶段，用来分支
    public bool isHidden;                 // 隐藏解：不参与常规通关，用于解锁隐藏内容
    public CellState[] cells;             // 长度同上
}
```

**约束（编辑器工具会校验）**：

- `initial.cells` 里 `pieceIndex` 必须是 **0..N-1 的完整排列**（每块图恰好出现一次）；错乱块用 `-1`，允许重复。
- `solutions[*].cells` **允许重复的 pieceIndex**——那是复制机制的正常结果。
- 每个 `solutions` 的 `cells` 长度必须等于 `gridSize²`。

### 4.4 操作集

```csharp
[Flags]
public enum PuzzleOps
{
    None         = 0,
    Select       = 1 << 0,   // 点选
    SwapAdjacent = 1 << 1,   // 平移：↑↓←→ 与相邻格交换
    Rotate       = 1 << 2,   // 旋转：H 逆时针 / K 顺时针
    Flip         = 1 << 3,   // 水平翻转：J
    Drag         = 1 << 4,   // 拖动
    Copy         = 1 << 5,   // 复制：C
    Undo         = 1 << 6,   // 撤回：Z
    Corrupted    = 1 << 7,   // 关卡内存在错乱块（只影响显示与判定）
}
```

**每关能开哪些操作由策划在 `PuzzleConfig.allowedOps` 里自己勾**，代码不做任何硬编码。
勾了哪个就只响应哪个按键/手势；底部提示行也是根据它自动生成的。

| 例 | 操作 |
|---|---|
| 第 1 关（只有平移） | `Select \| SwapAdjacent` |
| 第 2 关（加旋转/翻转） | + `Rotate \| Flip` |
| 第 4 关（加复制） | + `Copy \| Corrupted` |

> 仓库里 `L00_NewLevel.asset` 现在是 `Select | SwapAdjacent = 3`。
> ⚠️ `SwapAny`（任意两块互换）已从枚举删除，位值整体前移一位。
> 如果之前勾过旋转/翻转，**请在 Inspector 里重新确认一遍 `allowedOps`**。


## 6. 事件契约

用静态事件总线（两个人的项目，SO 事件通道太重）。双方只依赖这里的事件，不互相直接引用。

```csharp
public static class GameEvents
{
    // ── LevelDirector 发出 ────────────────────────────────
    public static event Action<LevelDefinition> LevelStarted;
    public static event Action<PuzzleConfig>    PuzzlePhaseEntered;   // 对方应禁用玩家控制
    public static event Action<PuzzleResult>    PuzzleAccepted;       // 判定通过
    public static event Action<int>             PuzzleRejected;       // 判定失败（参数暂为 0，预留重试次数）
    public static event Action<LevelContext>    ExplorePhaseEntered;  // 对方应启用玩家控制 + 跟随相机
    public static event Action<LevelDefinition> LevelCleared;

    // ── 其他系统发出 ──────────────────────────────────────
    public static event Action<string> ItemCollected;                 // 收集品 id
    public static event Action<string> InteractableTriggered;         // 可交互物 id（埋点/条件用）
}
```

订阅方（对方）至少要接：

- `PuzzlePhaseEntered` → `IPlayerControl.SetControlEnabled(false)`，关掉跟随相机。
- `ExplorePhaseEntered` → `SetControlEnabled(true)`，开跟随相机。
- `LevelCleared` → 播转场 → 加载下一关。

## 7. 我方提供的接口（对方实现 / 对方调用）

### 7.1 对方需要实现的三个接口

```csharp
/// 角色控制开关。拼图阶段会被禁用。
public interface IPlayerControl
{
    void SetControlEnabled(bool enabled);
    Transform Player { get; }
}

/// 对话。LevelDirector 播入场/通过/outro 剧情时调用。
public interface IDialogueService
{
    bool IsPlaying { get; }
    void Play(DialogueAsset dialogue, Action onComplete = null);
}

/// 转场。视觉与时长归对方，LevelDirector 只负责在中间点做事。
public interface ITransitionService
{
    /// atMidpoint: 画面全黑时调用（我这边用来切换阶段 / 加载场景）
    void Play(Action atMidpoint, Action onComplete = null, float fadeOut = 0.4f, float fadeIn = 0.4f);
}
```

> `DialogueAsset` 用你们现有的对话资产类型，我方只持有引用，不解析内容。

### 7.2 我方实现、对方调用的

```csharp
/// 所有可交互物的统一入口。对方的检测逻辑命中最合适的那个后调用 Interact。
public interface IInteractable
{
    string Prompt { get; }                 // 交互提示文本（"查看" / "捡起" / "进入"）
    bool CanInteract { get; }              // 条件未满足时返回 false（例如门需要先拼对）
    void Interact(GameObject interactor);
}
```

已规划的四个实现：

| 组件 | 行为 |
|---|---|
| `DialogueInteractable` | 调 `IDialogueService.Play` |
| `PickupInteractable` | 记入 `ProgressService`，发 `ItemCollected`，物件隐藏 |
| `DoorInteractable` | 调 `LevelDirector.NotifyDoorReached()`，触发过关 |
| `TriggerInteractable` | 只发事件 / 置 flag，不显示提示（地板机关类） |

### 7.3 LevelDirector 对外

```csharp
public class LevelDirector : MonoBehaviour
{
    public LevelDefinition CurrentLevel { get; }
    public LevelContext    Context      { get; }

    public void StartLevel(LevelDefinition level);   // 由关卡加载流程调用
    public void ConfirmPuzzle();                     // 由拼图 UI 的"确定"按钮调用
    public void NotifyDoorReached();                 // 由 DoorInteractable 调用
    public void RetryPuzzle();                       // 由"重新打乱"按钮调用
}
```

## 8. 进度记录

```csharp
[Serializable]
public class ProgressData
{
    public int version = 1;
    public string currentLevelId = "L01_HOME";
    public List<string> clearedLevels  = new List<string>();
    public List<string> collected      = new List<string>();   // "L01_PHOTO" …
    public List<string> hiddenSolutions = new List<string>();  // "L04_TWINS" …
}
```

**当前状态：只记内存，不落盘。**

- `ProgressService.PersistToDisk = false`（默认）。每次进 Play 都是干净的，**拾取物会重新出现**。
- 内存里仍然要记 —— 否则同一件东西能反复捡，隐藏结局也没法统计。
- 以后要做真存档：把 `PersistToDisk` 的默认值改成 `true`，就会读写
  `Application.persistentDataPath/progress.json`（写临时文件再替换，防写坏）。
- 调试用：`工具 → 清除进度存档` 会把磁盘上那份删掉。

对外只暴露 `ProgressService.HasCollected / Collect / MarkCleared / MarkHiddenSolution`，
不要到处直接改 `ProgressData`。

## 12. 配一个关卡的完整流程

> 对应代码已落地（M1a + M1b）：`Assets/Scripts/Data/`、`Flow/`、`UI/`、`Assets/Editor/`。

1. **出图**：正方形，边长取「格数 × 整数」（3×3 用 1536 或 960 就够，别用 4096）。导入设置保持默认 Sprite，**不需要开 Read/Write**。
2. 右键 `Create → Remiehzla → Level Definition`，命名 `L01_Home`，填 `levelId = L01_HOME`、`displayName = 家`。
3. 在 Inspector 里：拖入 `puzzle.image`，设 `puzzle.gridSize`（2/3/4），勾 `puzzle.allowedOps`（这一关允许哪些操作）。
4. 打开 `工具 → 拼图布局编辑器`：
   - 选「初始布局」→ 点「重置为正解形态」→ 用「随机打乱位置」或手动两两互换，摆出**策划设计的初始打乱状态**。
   - 点「＋新解」→ 选它 → 点「重置为正解形态」→ 填 `solutionId`（如 `normal`）。
   - 有隐藏解：再「＋新解」，勾 `隐藏解`，`solutionId` 例如 `hidden_twins`。
5. 填 `exploreSceneName`、`collectibles`（id 带关卡前缀，如 `L01_PHOTO`）。
6. 跑 `工具 → 校验关卡定义`，全绿才算配完。
7. 把该关卡挂到 `PuzzleGrid` 的 `level` 字段上（`LevelDirector` 会自动读同一个资产）。

**编辑器工具已实现的能力**：

- 网格里直接预览每块的画面、旋转、镜像效果（WYSIWYG）。
- 点一格选中、再点另一格 = 两块互换，和游戏里拖动的手感一致。
- 单格旋转 / 翻转 / 标记错乱块。
- 两种"一键重置"：「重置为正解形态」（每块归位且正立）、「全部摆正」（只清旋转）。
- 实时校验：初始布局是不是完整排列、解的格数、solutionId 是否重复、图片尺寸能不能整除等。

**注意**：改动是立即写回资产的（支持 Ctrl+Z），不需要额外保存；但 `gridSize` 在 Inspector 里改过之后，布局数组长度会不匹配，编辑器工具会自动补格，补出来的格子需要用「重置为正解形态」重摆。

## 13. 场景接线（当前状态）

```
Puzzle.unity
├─ Main Camera          正交相机（拼图阶段用不到，探索阶段用）
```

**A. 只想单独调拼图**：把 `ExploreRoot` 上的 `ExploreDemo` 删掉、`LevelDirector` 删掉，
就退化成纯拼图场景。

| 组件 | 用途 | 关键字段 |

## 15. 2D 遮挡（YSort）的表现与画法规矩

### 15.1 它是"整块换层"，没有渐变——这是设计如此

`YSort` 每帧只比较两个物体的脚点 y：

```
order = baseOrder + sortBias - 脚点y × orderPerUnit     // y 越小 → order 越大 → 画在前面
```

所以两个物体之间只有两种稳定状态 + 一次瞬间切换：

| 玩家脚点 vs 物件脚点 | 表现 |
|---|---|
| 玩家更靠上 | 物件整体盖住玩家 |
| 玩家更靠下 | 玩家整体盖住物件 |
| 交叉的那一帧 | **整块换层**（看起来像"突然弹出来"） |

一张 sprite 只有一个 `sortingOrder`，**物理上做不到**"上半截被挡、下半截露出"。
这是所有用单点 y 排序的 2D 游戏都有的现象，靠画法规避，不靠代码。

### 15.2 为什么占位色块特别明显

占位用的道具是**实心矩形**：玩家走到后面，整个矩形把他整个人盖住 → 看起来像"人消失了"。
换成真实美术（非矩形、有腿、有透明区域）之后，玩家站在后面本来就只被挡住一部分，
换层那一帧的变化量小得多，观感就正常了。

`ExploreDemo` 里的桌子已经改成「桌面 + 两条腿」，可以直接对比：

- 玩家从下面往上走 → 走到腿后面 → **从两条腿之间露出来**，而不是整个人消失。

### 15.3 美术/策划要遵守的三条

1. **pivot 放底部中点**。这样 `transform.position` 就是脚点，`YSort` 不用配 `footOffset`。
2. **需要玩家"绕到后面"的物件不要画成实心块**：桌子要有腿、柜子要有空隙、植物要有枝叶缝隙。
3. **一个物件由多张 sprite 组成时**，在物件根节点加 `SortingGroup` + **一个** `YSort`。
   `YSort` 会自动改 `SortingGroup.sortingOrder`，让整个物件作为一层排序，
   组内各 sprite 的 `sortingOrder` 自己定前后关系。

### 15.4 特殊物件：用 sortBias 手动控制

有些东西根本不该按 y 排：

| 物件 | 处理 |
|---|---|
| 地毯、地贴 | 固定 `sortingOrder` 很低，或者 `sortBias` 设成很大的负数 |
| 挂墙上的画、窗户 | 不挂 `YSort`，直接给固定的 `sortingOrder` |
| 天花板、吊灯 | `sortBias` 设成很大的正数，永远在最前 |
| 特定的"永远挡住玩家"的柱子 | `sortBias` 正数 + 关掉绕后可能 |

### 15.5 YSort 解决不了的情况

**又高、又能从前后两侧"穿过去"的物件**（床、门框、桥）：
单点排序必然在某一帧整块换层。做法是让美术把它切成两套图层：

- **后景层**：挂在 foot y 稍微偏上的位置；
- **前景层**：单独一个物体，foot y 偏下 + `sortBias` 正数，永远压在玩家上面。

玩家先走到后景层和前景层之间，看起来就是"从中间穿过去"。

> 想做"玩家被挡住时变半透明"也行（材质 + 碰撞触发），但成本和收益不成正比，暂时不做。
